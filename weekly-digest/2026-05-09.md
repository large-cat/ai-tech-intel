   - 📁 详见：[sources/anthropic-three-agent-harness.md](../sources/anthropic-three-agent-harness.md)

2. **Managed Agents产品化**（来源：Anthropic工程博客, 2026-04）
   - 将Agent拆解为Session（记忆）/ Harness（大脑）/ Sandbox（双手）三层
   - Harness与Sandbox解耦，性能提升：p50 TTFT↓60%，p95 TTFT↓90%+
   - 安全设计：凭证Token永不进入Sandbox可访问范围
   - 📁 详见：[sources/anthropic-managed-agents.md](../sources/anthropic-managed-agents.md)

3. **Opus 4.7模型迭代**（来源：Hugging Face Philipp Schmid评论, 2026-04）
   - 不到一年内第三代模型
   - 关键洞察：模型升级后，旧Harness的workaround会变成"死重"，需要定期Lint清理

**🔬 技术细节：Harness vs System Prompt**

| 维度 | System Prompt | Harness |
|------|--------------|---------|
| 本质 | 发给模型的一段指令文本 | 围绕模型运行的整个控制程序 |
| 功能 | 告诉模型"做什么" | 构建Prompt、调用API、解析输出、路由工具、管理状态 |
| 类比 | 一封信 | 整个邮递系统 |

**关键公式**：`Agent = Model + Harness`
- 传统SDD关注"代码如何运行"
- Harness Engineering关注"AI如何在环境中生存和决策"

**📊 数据点**
- Anthropic内部：Claude Code被定位为"an excellent harness"
- LangChain验证：仅优化Harness（模型不变），Terminal Bench 2.0从52.8%→66.5%，排名#30→#5
- Hugging Face Philipp Schmid："2026年最重要的学科"

## 🧬 重点技术深度分析

### 1. Harness Engineering：从Prompt到System

**背景**
2025年下半年，Context Engineering（上下文工程）成为热点——焦点从"写好一条指令"扩展到"设计动态系统来组装上下文"。但2026年一线实践者发现：光有好的上下文，Agent依然会失控。

**核心进展**

1. **PEV循环（Plan-Execute-Verify）**
   - 标准SDLC对Agent太慢
   - Agent写计划→在Sandbox执行→Verifier检查→失败重试
   - 无需人工干预的闭环

2. **Cognitive Memory > RAG**
   - RAG存储"是什么"
   - Cognitive Memory存储"为什么"——决策背后的理由
   - 防止多天长任务中重复犯错

3. **Failure Taxonomy**
   - 命名失败模式（缺失产物、错误路径、验证失败等）
   - 驱动自动化恢复

**关键分歧**
- **Anthropic**：Harness与模型协同进化，组件随模型升级而被淘汰，需定期Lint
- **Stripe**：确定性节点与Agent节点混合——可预测步骤交给代码，仅判断/创造环节调用LLM
- **LangChain**：最干净的验证——模型不变，Harness变，结果剧变

**产业链影响**
- 工具层：MCP协议月下载9700万+，成为Agent工具访问标准
- 评估层：89%团队实施了可观测性，仅52%实施了评估（Evals）——评估体系规模化是下一年的关键
- 人才层：AI工程师从"调Prompt"转向"设计Harness"

### 2. 存算一体/近存运算：从论文到产品前夜

**背景**
冯·诺依曼瓶颈：数据在CPU和DRAM之间搬运消耗60%+系统能耗。AI推理是内存带宽受限，而非算力受限。

**三大子方向成熟度**

| 方向 | 原理 | 当前状态 | 主要玩家 |
|------|------|----------|----------|
| Near-Memory Processing | 逻辑层紧邻DRAM/HBM | **最接近产品化** | NVIDIA(HBM4)、SK海力士(cHBM)、Google(3D-DRAM) |
| Compute-in-Memory | 在内存位单元内执行运算 | 实验室→原型 | 清华(RRAM-CIM)、Stanford、Purdue |
| Logic-in-Memory | 存储单元内嵌入布尔逻辑 | 早期研究 | 高校为主 |

**2026年产业信号**

1. **SK海力士 CES 2026**
   - cHBM：将GPU/ASIC功能集成到HBM基板
   - 信号：客户从"纯性能"转向"推理效率+成本优化"

2. **NVIDIA SRAM探索**
   - 片上SRAM减少数据移动
   - 但SRAM面积是DRAM的5-10倍，只能做小容量缓存

3. **Google 3D-DRAM chiplet**
   - 2024年专利，针对LLM serving优化
   - 低功耗、带宽优化的计算-内存chiplet

**关键瓶颈**
1. **128Kb阵列限制**：大多数CIM演示仍卡在此规模，模拟非理想性随规模扩大恶化
2. **软件链缺口**：缺乏CIM编译器、模拟器、映射算法——"软件-硬件协同设计缺口"
3. **精度vs能效**：模拟计算精度有限，需要数字校准电路

**产业链影响**
- 内存厂商从"供应商"转向"AI平台核心层"
- SK海力士"Full Stack AI Memory Creator"战略
- 软件链缺口催生新创业机会（CIM编译器、模拟器）
