## 1. NVIDIA Feynman 架构深挖

**来源**：The Next Platform, Tom's Hardware, TechInsights

### 工艺细节
- **TSMC A16 (1.6nm)**：非真正1nm，是TSMC第二代GAA工艺（N2P之后的下一代）
- **Super Power Rail (SPR) 背面供电**：从晶圆背面引入电源网络，正面完全留给信号线，解决FinFET时代信号线与电源线争夺空间的瓶颈
- **GAA晶体管**：全环绕栅极晶体管，比FinFET更精确控制电流，同功耗性能提升约15-20%
- **风险生产**：2026H2开始，2027年量产，2028年商用

### 硅光子集成
- 与Xanadu/Infleqtion等光量子公司合作
- 目标：芯片上光互连，10倍带宽提升
- 解决电信号在高端芯片上的功耗和延迟问题

### Groq LPU 整合传闻
- Jensen Huang暗示可能整合Groq的LPUs（Language Processing Units）
- Groq以确定性低延迟著称（<1ms/token）
- 若实现，将结合NVIDIA的生态系统+Groq的推理速度

## 2. SK海力士 cHBM "Stream DQ Architecture" 深挖

**来源**：The Next Platform, Tom's Hardware, SK海力士CES 2026

### 核心技术
- **Stream DQ Architecture**：在HBM的**base die**（最底层逻辑die）上实现定制计算逻辑
- 将HBM PHY（物理层接口）、内存控制器、甚至部分处理逻辑集成到HBM基板
- 传统HBM：base die只做简单的信号缓冲和电源管理
- cHBM：base die变成"小型SoC"，可执行客户定制的计算

### 性能提升
- SK海力士声称：最大推理吞吐提升约**7倍**（vs传统HBM配置）
- 减少数据在GPU和HBM之间的搬运

### 市场扩展
- 不仅是NVIDIA，Google、Amazon、Microsoft等超大规模云厂商也计划从**2027年**起定制自己的HBM
- 原因：各家的AI Workload不同，需要不同的内存-计算协同优化
- SK海力士预计：定制HBM将成为主流，而非边缘需求

## 4. Stripe Minions Blueprint 架构深挖

**来源**：Mitchell Hashimoto博客（Stripe工程师，HashiCorp创始人），Stripe工程博客

### 核心创新：确定性节点 × 智能体节点混合
Stripe内部自研的Agent编排框架，源于对Goose（Block/Square开源coding agent）的深度fork。

| 节点类型 | 示例 | 执行方式 |
|----------|------|----------|
| **确定性节点** | git commit、lint、测试、创建分支、推送PR | 硬编码，100%可预测 |
| **智能体节点** | "实现任务描述"、"修复CI失败" | AI自主决策，输出不确定 |

**状态机设计**：交替运行确定性代码节点和自由流动的Agent节点。创建分支（确定）→ 写代码（Agent）→ 运行测试（确定）→ 修复失败（Agent）→ 推送PR（确定）。

### 关键子系统
- **上下文工程（Context Engineering）**：规则按子目录条件应用，不是全局System Prompt。例如"只在infra/目录启用lint规则"，节省Token并减少误判。
- **Devbox**：10秒启动的隔离开发环境，Agent在此沙箱中运行。
- **MCP工具网络**：内部"Toolshed"服务器连接400+ MCP工具。
- **并行化**：同一Blueprint可在200+服务上同时运行。
- **多Agent协调**：不同Agent专精不同任务类别（前端、后端、安全审计），中央编排器分配。
- **人类审查红线**：AI只有提交权，没有合并权。

## 5. LangChain Terminal Bench 2.0 Harness优化深挖

**来源**：LangChain工程博客，Hugging Face Philipp Schmid评论

### 实验设计
固定模型（Claude 3.5 Sonnet），仅优化Harness，SWE-Bench Terminal 2.0从52.8%→66.5%，排名#30→#5。

### 优化维度

| 维度 | 具体措施 |
|------|----------|
| **System Prompts** | Reasoning Sandwich（xhigh规划→high实现→xhigh验证） |
| **工具设计** | LocalContextMiddleware（自动映射工作目录）、LoopDetectionMiddleware（N次编辑后注入"重新考虑"） |
| **Middleware层** | Trace Analyzer Skill：自动从LangSmith traces分析错误模式，类似boosting |
| **自验证循环** | 时间预算警告、测试要求提示、输出验证 |

### 关键发现
- **模型-specific Harness tuning**：不同模型需要不同Harness，Claude的Harness不能直接套到GPT上。
- **开源承诺**：公开了traces数据集和Deep Agents代码。

## 6. AMD MI450 vs NVIDIA Rubin 竞争深挖

**来源**：Tom's Hardware, Wccftech, HotHardware, AMD Financial Analyst Day

### 规格对比

| 指标 | AMD MI450 | NVIDIA Rubin Ultra |
|------|-----------|---------------------|
| **工艺** | TSMC 2nm | TSMC 3nm |
| **HBM容量** | 432GB | 576GB |
| **带宽** | 19.6 TB/s | ~22 TB/s |
| **FP4算力** | 40 PFLOPS | 50 PFLOPS |
| **FP8算力** | 20 PFLOPS | 35 PFLOPS |
| **功耗** | ~1500W | ~2300W |
| **关键客户** | Meta ($100B)、Anthropic、OpenAI | 几乎所有云厂商 |

### 关键变量
- **工艺领先**：AMD首次在工艺节点上领先NVIDIA（2nm vs 3nm）。
- **内存差距**：Rubin Ultra 576GB vs MI450 432GB，144GB差距在大模型训练中可能决定性。
- **功耗策略**：NVIDIA把Rubin功耗提升到2300W，用功耗换性能竞争MI455X。
- **市场份额**：NVIDIA~80%，但AMD+Meta $100B deal正在改变格局。
- **机架级设计**：AMD Helios含EPYC CPU + Pensando DPU + 开放网络标准，NVIDIA依赖NVLink。

## 7. 月之暗面 Kimi K2.5 深挖

**来源**：月之暗面官方博客，开源中国，行业分析

### 技术架构
- **1.5T混合token预训练**：视觉+文本联合预训练，非后期对齐。
- **零视觉监督微调**：仅用文本数据微调就能激活视觉推理能力。
- **Agent Swarm**：最多100个子Agent并行，1500次并行工具调用。
- **PARL训练**：Parallel-Agent Reinforcement Learning，端到端时间减少80%，效率提升4.5倍。
- **Kimi Code**：SWE-Bench Verified 76.8%，终端运行+VSCode/Cursor/Zed集成。

### 关键数据

| 指标 | 数据 |
|------|------|
| SWE-Bench Verified | 76.8% |
| Agent Swarm并行数 | 最多100个子Agent |
| 并行工具调用 | 1500次/任务 |
| API输入价格 | $0.6/M tokens |
| API输出价格 | $3/M tokens |
| License | Modified MIT（限制大型商业平台直接使用） |
| 估值 | $50亿 |

### 战略意义
- **价格屠夫**：API定价比OpenAI/Anthropic低一个数量级。
- **开源但不完全开放**：Modified MIT允许自托管，但限制AWS/Azure/GCP直接转售。
- **Agent原生设计**：模型本身为Agent Swarm优化，非"模型+Agent wrapper"。
